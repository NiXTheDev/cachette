> "A shared cache should not mean a shared bucket."

v1.2 makes the namespace the unit of identity. One cachette, one cluster, many forges — and the tenant comes from the CREDENTIAL, never from the request. The v1 key scope is client-controlled, and the HMAC payload's `<repo>><run>` is client-asserted, so neither can carry an identity the server can trust. Now they do not have to.

**What is cachette?** A self-hosted cache server for Actions-style CI. It speaks the real GitHub cache protocols end to end - the `actions/cache` toolkit's ArtifactCache (v1) and buildx's CacheService (v2, Twirp + Azure-style block blobs) - so your forge's Actions and your `type=gha` buildx exporter run against your own hardware with zero protocol adapters in between. Real clients round-trip byte-identically: @actions/cache, go-actions-cache, buildx. Not "compatible-ish" - the wire is the wire.

**What's new in v1.2:**

- **Namespaced storage (schema v3).** Every row carries a namespace, and it is part of the row's identity: the same key in two namespaces is two isolated entries with two payloads. A verified migration lands pre-v1.2 rows in the legacy namespace, which keeps the v1.1 id derivation verbatim — existing rows and blob files stay reachable. An index newer than the binary refuses to boot.
- **Per-request namespace resolution.** The auth gate resolves the credential to a namespace and every client-facing handler addresses storage through a `scoped()` view, so a tenant cannot observe or mutate another's rows even with identical keys and versions — and the same key reserved concurrently by two tenants is not a duplicate. Signed capability URLs MAC-bind the resolved namespace: a stripped or swapped `ns` is a mismatch, while pre-namespace URLs still validate to the legacy namespace.
- **Per-namespace quotas.** `[storage.quotas]` sets a `default` plus exact or tenant-side wildcard rules, most-specific wins. Only namespaces an admin explicitly maps into one namespace share a budget. An over-quota namespace is evicted first — worst excess first, LRU within it — before the global `min_free` floor reclaims anything; `eviction = "none"` leaves quotas advisory. v1 `cacheSize` reports the tenant's window narrowed by the global budget, and a periodic sweep enforces quotas continuously.
- **OIDC is per issuer.** `[auth.oidc."<issuer>"]` carries its own audiences, tenant claim, claim pins, trust roots and clock skew; the v1.1 flat table is rejected with a precise error naming the new form. The issuer is the forge and the value of `tenant_claim` (default `repository`) is the tenant — a token without the claim is rejected, never defaulted. `nbf` is now optional, as RFC 7519 requires; a present but non-numeric `nbf` is still a structural failure.
- **Forge runtime tokens (Plane B).** `[auth.runtime."<forge>"]` verifies HS256 tokens signed by a forge's general token secret read from a file at boot (empty or unreadable is fatal), with a configurable tenant claim, scope allow-list and claim pins. The v1 toolkit path has no other per-job credential, so runtime tokens are tried before OIDC — an HS256 token never reaches the RS256 verifier.
- **Namespace-aware cluster wire.** Every key-bearing peer request carries the resolved namespace and declares `x-cachette-peer-protocol: 2`. A missing or different version is refused with `426 Upgrade Required` — hello and heartbeat included — so a mixed cluster drains to "no healthy peer" instead of merging tenants' rows. Multi-tenant + cluster is now supported.
- **CDC completion (B-3).** The zero-ref purge now consults the referring entry's layout and namespaces (a complete `chunked` manifest counts as a referrer even if `refs` drifted; referrers from any namespace count), and crash bounds for whole-to-chunked conversion converge under boot + sweep with `used_bytes` on the at-rest invariant.
- **Build and CI.** Rust 1.100 and Zig 0.17.1; every external `uses:` resolves to hangar mirrors. The rustup mirror ladder probes the pinned channel manifest instead of `stable`, so a mirror that lacks 1.100 cannot win the race and 404 the toolchain install.

**Upgrading:** with no tenant-yielding plane configured, every credential still resolves to the legacy namespace and single-tenant deployments are byte-identical. Existing OIDC configs must move to the per-issuer block shape (the boot error names the new form), and a tenant-yielding plane requires `auth.mode = "bearer"` — HMAC stays single-tenant and is refused in a multi-tenant boot rather than degraded. See `docs/shared-cache.md` for the tenancy model and migration notes.

**Binaries** - 8 targets, native builds where the runners allow it:

- linux: gnu + musl, amd64 + arm64
- windows: gnu x86_64 (zig cc mingw), msvc amd64 + arm64 (cargo-xwin, clang-cl), gnullvm arm64
- `SHA256SUMS` attached - verify before running anything
